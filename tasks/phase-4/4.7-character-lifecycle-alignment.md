# Step 4.7 — Character Lifecycle Alignment

## Goal

Implement ACTIVE / ARCHIVED lifecycle on generic Character across persistence,
API list/filter behavior, and (where applicable) CharacterTools.

## Existing Context

- `CharacterLifecycleState` enum may exist in `backend/app/domain/lifecycle.py`
  with default ACTIVE on `GenericCharacter` — see 4.1 audit.
- No end-to-end archive/unarchive or filtered listing exists today.
- Hard delete remains available; do not model DELETED as lifecycle state.

## In Scope

- Persist `lifecycle_state` on generic Character
- Archive / unarchive operations (API and/or tools as scoped)
- Default active library lists exclude ARCHIVED characters
- Reversible archive (not tombstone / hard delete replacement)
- Tests for lifecycle transitions and list filters

## Out of Scope

- User-facing permissions for who may archive
- Campaign-scoped lifecycle
- Export/import lifecycle edge cases beyond 4.8 payload inclusion
- Generic AI infrastructure changes

## Required Interfaces

```python
class CharacterLifecycleState(str, Enum):
    ACTIVE = "active"
    ARCHIVED = "archived"
```

Repository and API must support filtering by lifecycle where list endpoints exist.

## Data/Persistence impact

`lifecycle_state` column on generic character storage (if not already added in 4.4).

## Acceptance Criteria

1. New characters default to ACTIVE.
2. Archive sets ARCHIVED; unarchive restores ACTIVE.
3. Default list endpoints exclude ARCHIVED unless explicitly requested.
4. Hard delete still works when safe; archive is not a substitute for delete.
5. Lifecycle tests green; full suite green.

## Required Tests

- ACTIVE default on create
- Archive / unarchive round-trip
- List filters: active-only default; optional include archived
- Archived character still retrievable by id if product rules allow

## Architecture Constraints

- Lifecycle is system-independent — lives on base Character, not D&D profile.
- Do not add lifecycle to generic AI tooling.

See `docs/DEFINITION_OF_DONE.md` + human review before ROADMAP `4.7` checkbox.
