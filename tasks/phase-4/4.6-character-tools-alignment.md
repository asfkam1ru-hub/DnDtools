# Step 4.6 — Character Tools Alignment

## Goal

Adapt `CharacterTools` and tool JSON schemas so AI tool execution reads/writes
D&D mechanics through the D&D profile boundary while base Character identity
remains system-independent.

Preserve the existing execution path:
`AgentService → ToolExecutor → CharacterTools handlers`.

## Existing Context

- `backend/app/tools/character.py` uses legacy `Character` monolith end-to-end.
- Tool definitions embed D&D fields in `create_character` / `update_character`.
- Stage 3 generic tooling (registry, validator, executor) is complete and stable.
- Persistence (4.4) and preferably API semantics (4.5) should be stable enough
  to define tool contracts.

## In Scope

- Update Character tool handlers to use split domain + repository
- Tool schemas: base vs profile fields (may retain compatibility flat create
  payload that creates base + D&D profile atomically)
- Preserve controlled error types (`CharacterToolInputError`, etc.)
- Update `tests/test_character_tools.py`, tool validation/execution/integration
  tests as needed

## Out of Scope

- Redesigning `ToolDefinition`, `ToolRegistry`, `ToolValidator`, `ToolExecutor`
- Changing `AgentService` or provider adapters
- New non-Character entity tools
- Campaign / runtime tools

## Required Interfaces

Existing tool names remain unless explicitly versioned:

- `get_character`, `list_characters`, `create_character`, `update_character`,
  `delete_character`

Handlers must route D&D fields through profile boundary; generic tool layers
must not import Character-specific code.

## Data/Persistence impact

Uses refactored repository from 4.4.

## Acceptance Criteria

1. CharacterTools aligned to profile boundary.
2. D&D validation preserved through tools (hp ≤ max_hp, bounds, etc.).
3. Tool execution still flows only through `ToolExecutor`.
4. Generic tool infrastructure unchanged (no new imports in registry/validator/executor).
5. `tests/test_character_tools.py`, `test_tool_validation.py` (character cases),
   `test_ai_integration.py` (character paths) green.
6. Full suite green.

## Required Tests

- Create/get/update/delete via tools with split persistence
- D&D validation failures through tool validator
- AI integration: agent creates character via tool executor (offline)

## Architecture Constraints

- Explicit `character_tool_bindings()` — no reflection dispatch.
- Generic tool layers must not import Character tools.
- Character tools may import repository and domain/profile types.

See `docs/DEFINITION_OF_DONE.md` + human review before ROADMAP `4.6` checkbox.
