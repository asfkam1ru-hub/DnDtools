# Step 4.5 — Character API and Schemas Alignment

## Goal

Adapt FastAPI routes and Pydantic API schemas so clients can work with the split
Character model: system-independent base Character plus optional D&D profile,
while preserving deliberate compatibility for existing D&D create payloads where
feasible.

## Existing Context

- Routes in `backend/app/main.py` use `CharacterCreate` / `CharacterResponse`
  mirroring monolithic legacy model.
- Persistence refactor (4.4) must be complete before API can store split models.
- Unified validation error contract via `app/errors.py` must remain stable.

## In Scope

- Update `backend/app/schemas/character.py` for base + profile shapes
- Adapt `/characters` CRUD routes
- Document compatibility shims vs breaking changes for existing JSON clients
- Create character with zero profiles (base only)
- Create/update paths that attach or update D&D profile when provided
- Extend `tests/test_characters.py`

## Out of Scope

- CharacterTools adaptation (4.6)
- Lifecycle archive/list filters (4.7)
- Export/import HTTP endpoints (4.8)
- User auth / ownership enforcement beyond passing through `owner_id` if exposed
- Generic AI infrastructure changes

## Required Interfaces

At minimum, distinguish API payloads for:

- Base Character create/update/response (system-independent fields + `owner_id`)
- D&D profile create/update/response (mechanics only)
- Combined compatibility response where existing clients expect flat D&D sheet

Exact schema names may vary; behavior must match acceptance criteria.

## Data/Persistence impact

Reads/writes through refactored repository (4.4). No new tables in this step.

## Acceptance Criteria

1. HTTP layer stores and returns data via split persistence model.
2. Validation errors remain unified contract (422 shape unchanged).
3. Zero-profile character create path works.
4. Existing D&D validation behavior preserved for compatible create/update paths.
5. `tests/test_characters.py` updated and green.
6. Full suite green.

## Required Tests

Migrate/extend `tests/test_characters.py`:

- Create base character without profile
- Create with D&D profile (compatibility path if exposed)
- CRUD round-trip preserves D&D validation rules
- 404/422 error contracts unchanged

## Architecture Constraints

- Schemas separate from domain models (Stage 2 pattern).
- Routes orchestrate repository; no D&D fields added to `GenericCharacter`.
- Do not alter ToolExecutor / AgentService contracts.

## Definition of Done

See `docs/DEFINITION_OF_DONE.md` + human review before ROADMAP `4.5` checkbox.
