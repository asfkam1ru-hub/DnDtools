## Goal

Establish the **system-independent base Character** as the primary domain
contract for identity, ownership, lifecycle metadata, and narrative fields.
D&D and other RPG mechanics must not live on this type.

Success = the system-independent base Character domain contract is finalized
as `GenericCharacter` (canonical rename to `Character` deferred until legacy
monolith retirement in Step 4.9 to avoid import ambiguity with
`app.models.character.Character`).

## Required Interfaces

```python
GameSystemId = NewType("GameSystemId", str)
DND_GAME_SYSTEM_ID: GameSystemId = GameSystemId("dnd")

class GenericCharacter(BaseModel):
    id: UUID
    owner_id: UUID  # required; neutral identity reference until User exists
    name: str
    description: str = ""
    biography: str = ""
    personality: str = ""
    notes: str = ""
    avatar: str | None = None
    appearance: str | None = None
    lifecycle_state: CharacterLifecycleState  # enum; behavior in 4.7
    created_at: datetime
    updated_at: datetime

class CharacterSystemProfile(BaseModel):
    id: UUID
    character_id: UUID
    game_system_id: GameSystemId
```

## Data/Persistence impact

None in this step. Domain contracts only. Persistence migration is 4.4.

## Acceptance Criteria

1. Base Character domain types import no FastAPI, SQLAlchemy, OpenAI, or tools code.
2. `GenericCharacter` requires `owner_id`; no silent default ownership.
3. `CharacterSystemProfile` stores relation identity only (no D&D fields).
4. `GameSystemId` is open-ended; adding future RPG systems does not require new
   enum members in generic core types.
5. A Character can be constructed at domain level with zero profiles.
6. Existing full suite remains green (`make audit`).
7. Legacy monolith may remain for compatibility during migration but is not the
   target primary domain type.
