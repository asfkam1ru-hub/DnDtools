# Step 4.10 — Core Alignment Integration Tests

## Goal

Add end-to-end integration tests proving the aligned Character stack works
across persistence, HTTP, and AI tool execution with the split model, and add
architecture guards preventing regression to the monolith pattern.

## Existing Context

- Stages 1–3 integration tests assumed monolithic Character.
- Steps 4.2–4.9 migrate domain, persistence, API, tools, lifecycle, tests.
- `test_ai_integration.py` already exercises AgentService + ToolExecutor +
  CharacterTools offline — must pass with aligned model.

## In Scope

- Cross-layer integration tests: create base Character → attach D&D profile →
  read via API → mutate via tool → verify persistence
- Zero-profile character path through API/tools if product-exposed
- Architecture tests preventing D&D fields on `GenericCharacter`
- Full regression suite as gate
- Document completion criteria for Stage 4 alignment

## Out of Scope

- Campaign / runtime / multiplayer scenarios
- Network OpenAI calls (keep offline stubs)
- New generic AI infrastructure

## Required Interfaces

No new public APIs required unless gaps found during integration testing.
Existing routes and tools must compose correctly.

## Data/Persistence impact

Uses production-aligned stack from 4.4+; temporary SQLite in tests.

## Acceptance Criteria

1. Integration test covers HTTP + persistence + tool path for D&D character.
2. Integration test covers zero-profile base Character if exposed.
3. AI integration test (`test_ai_integration.py`) passes with aligned CharacterTools.
4. Architecture checks enforce base/profile boundary.
5. Full `make audit` green.
6. Stage 4 alignment verified for human ROADMAP sign-off.

## Required Tests

New or consolidated integration module (name may vary), e.g.:

- End-to-end character create/read/update/delete with profile
- Agent tool create character persists split model correctly
- Architecture: GenericCharacter field inventory excludes D&D mechanics

## Architecture Constraints

- Integration tests remain deterministic and offline.
- Do not weaken architecture checks to pass.

## Definition of Done

See `docs/DEFINITION_OF_DONE.md` + human review before marking Stage 4
complete on ROADMAP.
